Sensor Role Architecture

Navigation — LiDAR

The 360° LiDAR is the robot's primary sense of space. It feeds every navigation decision — from path planning to real-time obstacle avoidance — completely independently of the camera system.

  • Full 360° point cloud at 10 Hz
  • EKF fusion with IMU + encoder odometry
  • Obstacle proximity → Safety Guard braking
  • Map-building for SLAM in future phases
  • Publishes to /awr/scan
Primary Navigation Deterministic Safety

Recognition — Pi Camera

The camera is dedicated exclusively to identifying what the robot is picking up or passing. It runs a Tiny-YOLO detection pipeline in a separate ROS 2 node — the navigation stack never waits on it.

  • Tiny-YOLO v4 — box, label, SKU detection
  • OpenCV pre-processing — crop, contrast, barcode
  • ESP32-CAM optional second shelf angle
  • Runs in parallel — does not block LiDAR pipeline
  • Publishes to /awr/items_detected

Planned Component Breakdown

Compute — Raspberry Pi 4

The planned onboard brain. Runs ROS 2 Humble, PPO inference at 15 Hz, LiDAR scan processing, and the Safety Guard Node simultaneously on 4 GB LPDDR4 RAM.

  • Quad-core Cortex-A72 @ 1.8 GHz
  • 4 GB LPDDR4 RAM
  • USB 3.0 for LiDAR & camera
  • GPIO I²C bus for IMU
Primary ComputeSpecced

Actuation — Differential Drive

Two independently driven wheels enable zero-radius turns and precise odometric tracking — critical for tight warehouse aisle navigation.

  • L298N dual H-bridge motor driver
  • PWM speed control per wheel
  • Quadrature wheel encoders (odometry)
  • 5 V / 3 A regulated power rail
PWM ControlEncoder Feedback

Navigation — 360° LiDAR

The robot's primary spatial sense — generating a dense point-cloud map for real-time navigation and collision avoidance across the full warehouse floor.

  • RPLIDAR A1 / A2 — 360° planar scan, 12 m
  • ~8,000 samples per revolution at 10 Hz
  • MPU-6050 IMU — 6-axis roll / pitch / yaw
  • LiDAR + IMU + encoder fused via EKF
360° LiDAREKF FusionPoint Cloud

Vision — Box & Item Recognition

Dedicated to identifying boxes and warehouse items on shelves and the floor. Completely decoupled from navigation — the camera is a pure recognition pipeline running in its own ROS 2 node.

  • Pi Camera Module 3 — high-resolution capture
  • Tiny-YOLO v4 — box / SKU / label detection
  • OpenCV pre-processing — crop, contrast, barcode
  • ESP32-CAM optional second shelf angle

Upgrade & Fallback Paths

LiDAR Upgrade

The RPLIDAR A1 can be swapped for the RPLIDAR A3 or Hokuyo UST-10LX in higher-demand deployments — extending range to 25 m and boosting scan rate for faster aisle traversal.

Optional Upgrade

Edge Inference

Both PPO inference and YOLO detection can migrate to a Coral USB Accelerator or TensorRT runtime — dropping combined latency below 20 ms and freeing CPU for full LiDAR map processing.

Roadmap

IMU Upgrade

The MPU-6050 can be upgraded to a BNO055 for absolute orientation and better heading stability — particularly useful once real-world drift is characterised against LiDAR ground truth.
